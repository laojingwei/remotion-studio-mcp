# 文字事件：读窗、断行、手法谱系

文字先承担句意，再承担动作。这一篇回答的是「这句话在屏幕上要停多久、断在哪、用哪个版式」——
比"加个动效"靠前一步，也是用户说"字看不清 / 一闪而过 / 像 PPT"时该查的地方。

> 通用排版基准（字号、行高、字距、字体搭配）在 `craft` §12，这一篇只补它没写的三件事：
> **读窗够不够、断行断在哪、fy 那套手法在我们引擎里对应哪个版式**。

## 一、先算够不够读

读速取 **每字 0.25 秒（4 字/秒）**，区间 0.22–0.3 秒/字——和 `subtitle` / `script` 的
字幕时长规则同一套，别在这篇里另立一个数。它不是标准，是下限保护：低于它观众只能"看到"不能"读到"。

| 一屏字数 | 最短读窗 | 30fps 帧数 |
|---|---|---|
| 6 | 1.5s | 45 |
| 10 | 2.5s | 75 |
| 14（字幕目标长度） | 3.5s | 105 |
| 18（单屏上限） | 4.5s | 135 |
| 26（硬上限，check_project 会拦） | 6.5s | 195 |

**读窗从"最后一个必要的字落稳"开始算**，入场那 9–12 帧不计入。所以一幕的最短长度是：

```
幕长 ≥ 入场(9–12 帧) + 读窗(字数 × 0.25s × fps) + 退场(6–9 帧)
```

18 字要 4.5 秒——这就是为什么一屏字幕别写满：**字多是靠拆句解决的，不是靠压停留**。

口播片反过来用：**幕长由 TTS 实测决定**（`tts_narration(mode="timing")` 回填），公式变成验收——
TTS 给的时长 < 读窗，说明这句字幕在这幕里读不完。三种修法，按代价从低到高：

1. 拆成两句、两幕（最便宜，也最符合口播节奏）
2. 压缩这句话（删修饰，不删主谓宾）
3. 把这条从字幕移到大字（大字可以停留更久，字幕不行）

数字、专名、陌生术语再各加 0.3–0.5s：读"12.8 万"比读"很多"慢，读"渗透率"比读"比例"慢。

## 二、断行是语义分组，不是按长度切

中文没有空格。按字数自动折行会把「不是准备充分 / 才开始」切成「不是准备充 / 分才开始」——
意思直接反了，这是最贵的错。

**一行 = 一个意群**。我们的大字类版式（`bigtext` / `maskreveal` / `kinetic`）都吃多行，
把意群显式写进去，别指望自动折行：

| 原文 | 错的断法 | 对的断法 |
|---|---|---|
| 不是准备充分，才开始 | 不是准备充 / 分才开始 | 不是准备充分，／才开始 |
| 三个月从 0 到 12 万 | 三个月从 0 / 到 12 万 | 三个月，／从 0 到 12 万 |
| 你缺的不是设备 | 你缺的不 / 是设备 | 你缺的不是设备（一句不切） |

断行之后再看每行长度：中文一行 14–22 字（大字页 6–12 字更稳），超过就把意群再拆一层。
**不要为了塞进模板缩字号** —— 缩到看不清比换版式贵得多。

## 三、一次文字事件的四段

| 段 | 时长 | 我们怎么实现 | 常见错 |
|---|---|---|---|
| 准备 | 0–0.3s | 上一幕末尾让位（`anim` 收 opacity） | 上一幕大字还压着，下一幕已经在读 |
| 进入 | 0.2–0.5s（6–15 帧） | 版式自带入场，或 `anim[].from/to` | 逐字发射等长，读起来像机器 |
| 读窗 | 按上一节算 | 版式停留，不加额外动作 | 读窗里叠一个大动效，焦点被抢走 |
| 退出 | 0.15–0.4s（5–12 帧） | 转场带走，或 `anim` 收 | 淡到 30% 还留着 → 观众以为没读完 |

**并行动画不得占用读窗焦点**：背景在流动、粒子在下落都没问题（低幅度、无信息），
但读窗里出现第二个"要看的东西"（新元素入场、大字换位）就等于把这句作废。

## 四、手法谱系 → 我们真实的版式

fy 的 13 种动态字手法，在 Remotion 版式引擎里只有一部分有对应实现。**没有对应的一律走降级**
（`get_guide("style-translate")` §八的三条路径），别硬说「做到了」：

| 想表达 | 我们的 type | 什么时候别用 |
|---|---|---|
| 逐行从裁切框升起（金句、结论） | `maskreveal` | 超过 4 行就挤，拆幕 |
| 整块砸下来（必须记住的那一句） | `stomp` | 全片最多两次，每次都砸等于都不重要 |
| 逐字打出（条款、步骤、要被读完） | `typewriter` | 口播片别用：字幕已经在读，再打一遍是拖 |
| 关键词被扫亮（长句里挑起一个词） | `highlight` | 一句话只能亮一个词，亮两个等于没亮 |
| 数字从 0 滚到目标（金额、涨幅） | `counter` | 数字与图形必须同源；别让条形和数字各自滚 |
| 乱码收敛成真字（科技结论、数据揭示） | `scramble` | 关键事实别留乱码；收敛后要给完整读窗 |
| 渐变流动的口号/章节标题 | `gradienttext` | 正文不用：流动的字读着累 |
| 信息很多、节奏很赶 | `marquee` | 超过 8 秒就是噪音 |
| 逐条落位（要点、清单） | `bullets` / `list` / `steps` | 5 条以上换 `list`，`bullets` 上限 5 |
| 情绪停顿、只有一句话 | `quote` / `bigtext` | 一句超 12 字换 `maskreveal`（能分行） |

**我们引擎没有的**（fy 有、这里没有，写清楚免得 agent 编）：
字重轴向呼吸、轮廓到填色、真实笔顺书写、粒子聚字与散字、挤出立体字、字形拓扑变形、拆字表意。
遇到这类需求，正确做法是**挑一个语义接近的版式 + 用配色/节奏还原气质**，并在回执里说明走了降级路径。

## 五、三级力度：写清"为什么强调"

同一部片子里，文字的强度要分三层，否则每一句都在喊，等于没有重点：

| 级别 | 手段 | 用在哪 |
|---|---|---|
| 一级 | 颜色 / 字重 / 底色块 | 段内的关键词，多数强调停在这一层 |
| 二级 | 加空间变化（位移、缩放）或主体回应 | 每段 1–2 处 |
| 三级 | 停顿后爆发，或突然安静；`stomp` / 全屏冲击 | 全片 1–2 处，只给真正的转折 |

**每一处强调都要能回答"观众应该理解什么变化"**。答不出来就别强调——
`stomp` 砸在一句废话上，观众记住的是"这里很吵"。

## 六、返修表

| 症状 | 先查什么 | 修法 |
|---|---|---|
| 字一闪而过，观众没读完 | 读窗 vs 字数（第一节的公式） | 拆句分幕；或从字幕移到大字 |
| 断行后意思变了 | 意群是否被切开（尤其"不是/不/没"后面） | 显式写行，不靠自动折行 |
| 看着像一页 PPT | 这一幕有没有承担关系（`get_guide("meaning")`） | 换承担关系的版式，不是加动效 |
| 每句都在动，很吵 | 三级力度的分布 | 多数句停在一级；三级全片只留 1–2 处 |
| 字被裁 / 出界 | 元素位置与字号（`elementEdgeWarn` 会提示） | 缩字号或换行；别靠加 `maxWidth` 硬挤 |
| 掉字、显示成方块 | 字体是否含这几个字（换字体前 `preview_frames`） | 换字体或补字；字号救不了缺字 |
| 字幕和画面大字抢注意力 | 两处是否在说同一句 | 大字讲结论、字幕说过程，别重复 |
