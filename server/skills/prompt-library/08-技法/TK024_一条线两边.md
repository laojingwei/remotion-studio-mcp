# TK024 一条线两边

- 类型：单技法
- 时长：6–12 秒（分割线摆动一个来回约 10.5 秒）
- 长什么样：一条几乎竖直的白线把画面劈成两半，左边下雨、右边浮着暖光，两边的字一左一右对称落位。
- 适合：以前和现在、他们和我、之前之后，两边差别要一眼看出来
- 关键词：分屏、对比、分割线、冷暖
- 画风耦合：绑在媒介上
- 出处：原「技法」代码样片 F3 · data/archive/upgrade-source/02-手法/（原件归档）

## 提示词

**什么时候用**：讲「以前和现在」「他们和我」「之前之后」——两个状态并置，让观众自己得出差别。它不解释，只并列；所以两边的差别必须一眼能看出来（下雨对暖光、冷对暖、空对满），靠文字说明的对比，用分屏是浪费。

**分割线**：位置在画面正中，再叠一个摆动：50% + sin(秒 × 0.6) × 4% 的画宽。一个来回约 10.5 秒，幅度只有 4%——它是在呼吸，不是在扫过。别做成从 0 扫到 100% 的擦除，那是转场，不是分屏，语义完全不同。

**左边（以前）**：竖直渐变 #1a1e26 到 #0b0d11，上面压 90 条雨丝：颜色 rgba(170,185,205,.35)、线宽 1，每帧向下走 220 × 速度 px 每秒（速度取 0.5 到 1.5 之间），每条长 12 × 速度，末端向左偏 2px——所以雨是斜的，斜度约 9.5 度。每条雨的起始位置和速度是固定种子生成的常量，**不能每帧重随机**，否则雨会抽搐。

**右边（现在）**：径向渐变，中心在画面 75% / 60% 处、半径 60% 画宽，从 #3a2410 到 #120b05；上面浮 40 个暖光点，颜色 #ffb664，半径 3 到 12，向上浮 8 到 22 px 每秒，透明度在 0.4 到 0.7 之间按 sin(秒 × 2 + 初相) 呼吸，约 0.32Hz。必须用叠加混合，光点才会发亮；用普通混合就是一堆土黄色圆片贴在上面。

**两侧的标签**：左边「以前」、右边「现在」，字号 = max(11, 短边 ÷ 16)，横屏 1080 时约 67；衬线体、字重 700；距画面短边 6%，左上与右上对称。左边色 rgba(210,218,230,.85)，右边 rgba(255,226,180,.92)——两边不是同一个白，右边偏暖，这一档色差是刻意的，别统一。

**分割线本身**：rgba(255,255,255,.7)，宽 1px，贯穿全高。就一条线，不加光晕、不加双线、不加箭头，它越不起眼，两边的对比越强。

**怎么在我们工具里做**：add_scene 一幕，左右各建一个容器组，各自用一个矩形遮罩裁到分割线的位置（裁剪边界逐帧跟着分割线走；如果组裁切不支持，降级成固定 50/50 的硬分屏，只用 8 帧一步的细碎位移近似摆动，幅度降到 1%，否则会看得出台阶）。左组里放雨丝线段（90 条太多，减到 45 条、每条加长一点，密度看起来差不多），右组里放光点。两侧共用一条时间轴：换文案、换场景都卡在同一批时间点（比如 0 / 2.4 / 4.8 秒各一次），别让一边先动一边后动——分屏最怕左右不同步，观众会以为在比「谁先」。

**禁止**：分割线扫过（那是转场）；左右出现第三种色调；两边字号不一致；分割线加光晕或做粗；某一侧单独做入场动画；两侧各用一套时间轴。

**什么时候不成立**：两侧内容体量差太多（一边两个字一边二十个字，空的那侧会像没做完）；画幅比窄于 4:3（每侧只剩不到 46% 宽，字会挤成竖条）；需要看清细节（分屏把每一侧都压掉一半，人脸和产品都不该用）；两边差别需要解释才能懂（那就该用别的手法，不是分屏）。

**验收**：preview_frames 抽 0.5 秒和 5.5 秒——分割线的横向位置必须差出 2% 到 8% 画宽，雨的整体位置必须下移；render_preview_clip 看两侧节奏是否恒定（雨速和光点速度不能一下快一下慢）、分割线摆动是不是连续的，不能一顿一顿。
