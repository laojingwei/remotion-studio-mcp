# 意义→画面（meaning）

> **什么时候读这篇**：写分镜之前（`start_guide` 第 9 步）、用户说"像 PPT / 没讲清 / 太散 /
> 故事没展开"的时候。
>
> 这一篇只回答一个问题：**这句话该让观众看懂什么变化。** 答不出来就该合并或删掉这一幕，
> 而不是给它加动效。文字只负责命名和解释，变化由画面对象承担。

## 一、先承认一件事：我们最容易做出来的片子是"逐句贴卡"

口播有 20 句，就做 20 幕；每幕一个标题 + 两行正文 + 淡入。技术上台台过关，
`check_project` 全绿，用户看完说"像 PPT"。

病根不在动效，在**没有一幕承担"关系"**。所以分镜阶段就要给每幕标一个关系类型
（`Shot.relation`），标不出来的幕要么合并，要么承认它只是换页。

## 二、七类关系 → 可视频操作 → 怎么落地

**每类都要问一句"证据是什么"**：观众凭什么相信这个变化发生了？

| 关系 | 观众要看到的变化 | 必须成立的证据 | 落地做法（默认可用的 type 与 freeform） | 常见错误 |
|---|---|---|---|---|
| **因果** `cause` | A 先改变，经过可见路径影响 B | **触发先于反应**；承载对象连续 | `freeform` 里两个对象 `anim` 起始帧错开 10–20 帧；流程用 `wipe` 逐行推开（先出现的那行是原因） | A、B 同时弹出 → 只表达了并列，没表达因果 |
| **否定对比** `contrast` | 保留同一比较维度，撤掉/改写错误解释 | 两状态**可比**（同坐标、同单位） | `freeform` 左右两栏同网格；旧解释整栏压暗/褪成灰，新解释才上强调色 | 用炸裂效果掩盖"解释被替换"；两个状态不在同一维度上 |
| **部分整体** `whole` | 从真实分件装配到整体 | 数量、连接方式、归属正确 | `freeform` 分件逐个归位；零件级拆解交 `iso`（可逐帧高亮讲解） | 随机粒子聚合——看着热闹，说明不了功能分工 |
| **尺度** `scale` | 同一对象拉远，逐层揭示 | 小层仍可追踪；尺度标签真实 | `freeform` 全屏图 + scale 关键帧；空间尺度交 `scene3d` 的相机拉远 | 每章换一张无关图，层级断了 |
| **取舍** `tradeoff` | 分支与代价同时显现，只选中一条 | **被放弃项不是伪劣稻草人** | `freeform` 画分叉路径，落选支压暗、选中支加粗；两选项并列同一视觉权重 | 所有分支都变绿 = 没有取舍 |
| **累积** `accumulate` | 时间轴 / 留痕 / 层叠 / 增长 | 时点与数量**有来源** | `counter`（数字滚）；时间轴、进度环、柱列都在 `freeform` 里用 shape + 关键帧画 | 用没来源的数字"制造具体感" |
| **感受转变** `feeling` | 姿态、空间、颜色、速度**共同**变化 | 情绪来自前因；允许停顿 | 没有专用 type：`set_theme` 换色 + `set_scene_backdrop` 换氛围 + 换动效节奏（三种一起换） | **只换背景颜色**——这是最常见的偷懒，观众感觉不到 |

`plain` = 纯转场/封面/落版，不承担关系。**一部片子里 `plain` 超过一半，基本就是逐句贴卡。**

## 三、抽象主题先选一个"能持续变形的载体"

线、纸面、窗口、路、群体、机械件。**不是每个名词都配一个图标**。

选定的载体要能贯穿多幕（这就是 `Shot.carry` 要写的东西）：第一幕是线，第三幕它绕成结，
结尾松开——观众会自己接上，不需要字幕解释。

物理隐喻可以用，但别伪装成真实测量（示意图就标示意图）。

## 四、分镜构造五条

1. **先写主线再分摊**：用一两句写整篇"提出 → 解释 → 证据 → 限制/反转 → 落点"。
   没有反转就**不要强造**反转（硬造的反转比平铺更假）。
2. **一段可以多镜，一句也可以跨镜**。镜头怎么分由理解需求、空间关系、声音句读决定，
   不由句号决定。
3. **关键概念第一次出现要给读时**（大字至少停留 1.2 秒 / 8 字以内）；已识别的对象后面可以快。
4. **动作三段**：前面交代对象 → 中间展示变化 → 后面留结果窗口。读完最后一行再切。
5. **写相邻幕的交接**：同一对象 / 形状 / 方向 / 颜色 / 声音（`Shot.carry`）。
   接不上的地方允许**明确硬切**，别硬凑转场。

## 五、四个词进来，各自查什么

| 用户的原话 | 先查 | 最后才查 |
|---|---|---|
| **像 PPT** | 画面里是不是只有名词陈列？补一个**真实的关系变化** | 不要自动加镜头震动 |
| **没讲清** | 条件、因果方向、证据、阅读窗 | 缓动和时长 |
| **太散** | 有没有贯穿对象；同时变化的维度太多 | 分章风格是否统一（先保对象身份与文案层级） |
| **故事没展开** | 关键过程、选择、后果的**时间**够不够 | 不要每段平均拉长 |

**顺序不能倒**：先改意思，再调效果。反过来做，用户会一直说"还是不对"。

## 六、两个自检（分镜阶段就能做，别等成片）

1. **遮住标题看正文**：挡住所有大字，还能看出这一幕在说什么吗？看不出 → 是版式问题，不是字号问题。
2. **只读大字**：把所有幕的大字连起来读，是一个完整故事，还是一堆标签？是标签 → 回第二节补关系。

这两条现在会出现在 `save_storyboard` 的回执里，写完分镜就能看到。
