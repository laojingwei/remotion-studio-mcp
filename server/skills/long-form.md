# 长片章节指南（超 12 幕或超 2 分钟）

长片与短片的差别不是"幕更多"，而是**要按章组织**：规划、制作、音频、验收都以章为单位。
不做章节划分的 30 幕工程，改一处就要全片来回对，agent 和用户都会累。

（方法论源自 garden-skills/motion-showreel 的 long-form.md，按本工程单工程多轨模型改写：
本工程没有独立章节文件，**章 = 幕的分组**，落在分镜表与命名里。）

## 1. 先规划内容，再分章

- 需求确认时明确总时长与浮动范围；口播实际时长与目标不符先停下确认，不自动截断。
- brief 里写清：章节数、每章目的与时长、章间衔接、贯穿全片的元素（同一主角/同一转场语法/同一配色）。
- **先分章、后分幕**：按内容边界拆章，每章 6–10 幕（30–90 秒）比较顺手；这是工作节奏建议，不是叙事规则。
- 长片可以有多个重点，**不必把短片的高密度拉满整片**；字体、色彩、图形含义贯穿，变化服务于讲述。

## 2. 章节怎么落在工程里

- 分镜表（storyboard）里用 `name` 标注章：`第1章·开篇`、`第1章·痛点`…；或用 `note` 记「第 N 章开始」。
- 每章第一幕用一个可辨识的开场处理（章节标题 `title` 幕、或固定转场语法），观众能感到章节边界。
- 章内承接照常（`get_guide("craft")` §3 三问）；**章边界允许有意的硬切**，但别让技术切片制造随机跳变。

## 3. 音频按章制作

- 口播按章分段合成：`tts_narration` 每章一次（`applyToScenes=true` 会重写该幕时长与字幕，逐章做避免大面积对齐返工）。
- 用户给整段口播长稿时，先按自然停顿切章，切分不得丢字；原始稿保留。
- BGM 按章对位：每章选段落，章边界处设计延续或淡出，**不能把拼接当任意截断音乐的理由**。
- 有人声的章按 `get_guide("sound")` §5 避让。

## 4. 分章验收（关键差异）

- **每章做完先验**：`preview_frame` 抽本章首/中/尾，用户确认这一章再进下一章——不要全片建完才给用户看第一眼。
- 章末与下一章开头**连着看一遍**：`preview_frame` 抽章末最后 1 帧 + 下章前 2 帧，检查承接与字幕。
- 全片建完后：`check_project`（硬问题）→ `render_video(dryRun=true)`（音频超长/缺失）→ 抽帧复核 → 渲染。
- 总时长核对 ±10%；超了先和用户确认砍哪章，不擅自加速口播或截断。

## 5. 省 token 与返工的实操

- 改某一章文案只动该章幕，别整包回读：`get_project` 看骨架即可。
- 主题/配色一次定好再铺幕：30 幕工程中途 `set_theme` 改色，等于全片重验一遍。
- 元素时长不随幕长自动变：**先 `tts_narration` 定幕长、再放元素**，长片尤其要守这个顺序，
  否则每章都要回头修「元素中途消失」。
