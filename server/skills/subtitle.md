# 字幕写法（一屏一句，不带标点）

字幕是成片里最容易被做坏、也最容易看出业余的一层。做坏的方式只有一种：**一屏字太多**。

## 1. 硬规矩（不是建议）

| 规矩 | 数值 | 为什么 |
|---|---|---|
| 一屏字数 | **8–16 字，最多 18** | 一屏就是观众一眼能扫完的量，超过就是让人「读」而不是「看」 |
| 标点 | **上屏不带标点** | 逗号句号在画面上是噪音，标点只用来在稿子里断句 |
| 一屏行数 | 1 行（最多 2 行） | 两行以上会压住主体，也来不及读 |
| 停留时长 | 每字约 0.22–0.3 秒（≈3.5–4.5 字/秒） | 比这快就是闪一下；比这慢会让人等下一句 |
| 断句位置 | 语义边界，不在词中间断 | 「我们今天 / 讲三件事」可以，「我们今天讲 / 三件事」不行 |

**自检一句话**：把一屏字幕念出来，一口气念不完，就是太长了。

## 2. 不要自己拆，但要会看

`set_subtitle` / `build_storyboard` / `tts_narration` 写入时都会自动拆：

- 清标点（`3.5%`、`1,200` 这种数字里的点和逗号保留）
- 按标点断句 → 过长的按虚词（的 / 了 / 着 / 吗 / 呢…）再断 → 过短的并到邻句
- 每屏上限**跟着字号走**：字号 2.6%（默认）→ 18 字；字号 4.5% → 约 16 字；6% → 约 12 字

所以你的工作不是拆，而是**看完返回里的拆分预览**：

```
「开场」字幕已写入：3 屏（每屏 ≤ 18 字，46 字→46 字）
  1. 今天讲三个方法（7 字）
  2. 第一个几乎不花钱（8 字）
  3. 但大部分人做反了（8 字）
```

拆出来的句子读着别扭（断在奇怪的地方），说明**稿子本身是书面语**——回去改稿，别指望机器断得漂亮。

## 3. 老工程 / 用户塞进来的长字幕

存着的字幕如果是长句（几十字、带标点），渲染时虽然会自动拆，但断点是机器猜的，节奏不一定对，SRT 也会跟着碎。

```
fix_subtitles(dryRun=true)   # 先看会拆成什么样
fix_subtitles                # 确认后落盘
```

`check_project` 会把超过 26 字的字幕标成 ⚠️，`render_video` 会**直接拒绝**（除非 `force=true`）——一屏读不完的字幕，渲出来就是废片。

## 4. 字幕和「屏幕文案」不是一回事

| | 字幕 | 屏幕文案 |
|---|---|---|
| 内容 | 配音说的话（逐字） | 提炼的关键词 / 数字 / 结论 |
| 位置 | 底部固定 | 版式内自由排版 |
| 字数 | 一屏 ≤18 | 标题 ≤9、正文 ≤18 |
| 谁读 | 关声音的人 | 开着声音也会看 |

**最常见的错误**：把字幕当屏幕文案用——一屏塞一句完整结论；或者把屏幕文案当字幕用——一屏只有「方法一」三个字，配音却说了一整段。

## 5. 双语 / 特殊场景

- 双语：一行中文一行英文，两行都算在「2 行」上限里；英文按字符宽度算，一屏别超过 32 字符
- 歌词 / 卡点：一屏一句歌词，强制跟着拍点切换（`set_beat_grid` 后按拍点设 time）
- 引用 / 金句：可以放大成「屏幕文案」单独做一幕，**不要**塞进字幕层
- 数字 / 价格：字幕里写阿拉伯数字（「3 个」「99 元」），不要写「三个」「九十九」

## 6. 检查清单（交付前）

- [ ] `check_project` 没有字幕 ⚠️
- [ ] `preview_frames` 抽 2–3 帧：字幕没压主体、没出安全区、没换行成三行
- [ ] `export_subtitles` 导出 SRT，随机挑 5 条看：每条都能一口气读完
- [ ] 字幕和 `brief.subtitleSpec` 一致（字号 / 位置 / 描边或底色 / 高亮）
