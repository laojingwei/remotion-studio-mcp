# 动作：机制、数值、转场与接缝

这一篇回答「这个动作该不该有、该多快、该用哪种转场、接缝为什么顿」。
组织方式按**症状**排，因为用户抱怨的是"看着黏""像玩具""这里断了一下"，不是"弹簧参数不对"。

> 运动质感→工具的对应关系在 `craft` §4，转场语法在 §5。这一篇补的是它们没写的：
> **错峰总长的算法、重量与接触、按两镜关系选转场、接缝的速度匹配**。

## 一、先问这个动作承担什么

四个合法用途，选不出来就是装饰，删掉：

| 用途 | 例子 | 删掉会怎样 |
|---|---|---|
| 引导 | 视线从标题带到数字 | 观众不知道先看哪 |
| 反馈 | 点击/落地的即时回应 | 感觉"没接住" |
| 关系 | A 变成 B、A 推向 B | 因果关系看不见了 |
| 转场 | 上一幕的结果交给下一幕 | 接缝生硬 |

**读文字的时候允许完全静止**：锁镜、只做 opacity 淡入、匀速位移用 `linear` 都合理。
不要把弹簧、模糊、粒子、连续微动硬加到所有风格上——这是"AI 味"最主要的来源之一。

## 二、时长与缓动的真实边界

元素的 `anim.ease` 只有这六个（写别的会被 schema 拒）：`linear / easeOut / easeIn / easeInOut / easeOutBack / spring`。
特效的 curve 是另一套（`linear / in / out / inOut`），两处别混。

| 场景 | 时长 | 30fps 帧数 | 缓动 |
|---|---|---|---|
| 微反馈（图标、强调线） | 150–200ms | 5–6 | `easeOut` |
| 常规入场（元素位移、淡入） | 300–400ms | 9–12 | `easeOut` |
| 场景级（整幕、大位移） | 600–800ms | 18–24 | `easeInOut` |
| 离场 | 进场的 60–75% | 6–9 | `easeIn` |
| 俏皮元素的回弹 | 400–500ms | 12–15 | `easeOutBack` |
| 需要真实物理感的落定 | 500–700ms | 15–21 | `spring` |

**过冲写成一个中间关键帧**：终点前放一个超出目标 5–8% 的帧再回落，比调 `easeOutBack` 更可控
（`anim` 三段：`[0,10]` 到 108%、`[10,16]` 回 100%）。

`linear` 不是"没缓动"，它是某些动作的正确选择：匀速滚动、跑马灯、持续旋转、进度条。

## 三、错峰：总长要算，不能猜

逐个入场时，**整组结束时间 = 单项时长 + (n−1) × 间隔**：

```
8 项，每项 200ms，间隔 50ms → 200 + 7×50 = 550ms
```

写成 400ms 结束，最后两项就永远看不到（或者被下一幕切掉）。3 条以内可以不算，
5 条以上必须算——`bullets`/`list`/`steps` 自带错峰，自定义 `anim` 时才需要手算。

错峰顺序按**信息顺序**或**空间顺序**，不要随机：随机错峰看起来像加载失败。
间距用 40–80ms；超过 120ms 整组会散，读的人会觉得"一个个蹦出来很慢"。

## 四、重量与接触

动作有重量的前提是**先画接触，再补预备和随动**：

| 阶段 | 做什么 | 时长占比 |
|---|---|---|
| 预备 | 反向收一点（缩小 5% / 后退几像素） | 主动作的 20–25% |
| 主动作 | 到位，可以带 5–8% 过冲 | 50–60% |
| 停留 | 停稳，把读窗留出来 | 按读窗算 |
| 随动 | 相关元素延迟 2–4 帧跟上（不是同时） | 10–20% |

**挤压要守恒**：球落地压扁时，横向放大多少、纵向就缩小多少（`sx × sy ≈ 1`）。
只压一边会像果冻，不守恒会像被捏。

**接触事件要对齐声音的峰值，不是音频文件的起点**：音效文件的 0 秒往往不是"啪"那一下。
`set_audio` / 音效片段留出 `peakOffset`（毫秒），让峰值落在接触帧上——差 3 帧以上就听得出错位。

**持续接触不能滑**：脚踩在地上时，脚的世界位置锁死，动的是身体；让脚跟着整体缓动滑出去，
是最容易被看出来"假"的一类错。

## 五、转场按两镜关系选，不按效果名选

先写清两幕的关系，再挑实现。效果名（"用个 zoom 吧"）不是理由。

| 两镜关系 | 首选 | 我们的实现 | 前提 |
|---|---|---|---|
| 同一对象进入下一步、因果接续 | 匹配剪辑 | `none`（硬切）+ 两幕主体位置对齐 | 对象身份真的相同 |
| 同一空间看另一部分 | 推移 | `slide` / `diagonal` | 方向要一致，别一左一右 |
| 从总体进入细节 | 穿越放大 | `zoom` + 下一幕从锚点展开 | 入点在哪要先定 |
| 时间经过、回忆、状态消融 | 叠化 | `fade` / `blur` | 叠在一起不能被读成同一时刻 |
| 明确对比、笑点、跳跃 | 有动机硬切 | `none` | 哪个变量保持、哪个突然变，要说得出来 |
| 章节换气质 | 遮罩/翻页 | `wipe` / `flip` / `circle` | 字体与角色身份要延续 |
| 没有可追踪的共同点 | 简洁硬切 | `none` | 别用炫技遮掩结构问题 |

三条硬约束（都是实测踩出来的，不是审美偏好）：

- **带字幕的幕，转场 ≤ 6 帧**。交叉期间上下两幕字幕会同屏，超过 8 帧能看到两行小字压一起。
- **上一幕的大字会半透明压在新幕上**（接缝是"叠"出来的）。要避免：提前 0.3s 收 opacity、缩短转场、或硬切。
- **全片只用 2–3 种转场**。12 种库里每种都用一遍，观众感受到的是"没有语法"。

## 六、接缝：同方向切点要匹配速度

同方向滑动交接时，两边的**速度**要接近，不只是位置对上：

```
出场：位移 dout / 时长 Tout      入场：位移 din / 时长 Tin
速度匹配：dout / Tout ≈ din / Tin
```

例：出场 230px / 0.33s（≈700px/s），入场若 0.42s 还走 230px（≈550px/s），接缝就会"顿一下"。
修法三种：把入场位移改成 292px、或入场也压到 0.33s、或明确接受速度变化并**实际看过接缝**。

另外两条：

- **晚卸载**：上一幕的层要留到新幕的第一帧可读之后才移除，早了会闪一下底色。
- **转场期间还在读的句子不要跟着缩放/模糊**。字幕和结论句留在屏幕层，等句子读完再换。

## 七、返修表

| 症状 | 先查什么 | 修法 |
|---|---|---|
| 每个元素都在弹，像玩具 | 材质和用途真的需要弹吗 | 改成 `easeOut` 单次；全片只留一处真正的反馈 |
| 看着黏、拖沓 | 尾巴是否占掉了读窗 | 缩时长或到位后明确停住；别无条件截断位置 |
| 列表最后一项没出现 | 错峰总长（第三节公式）、幕长 | 缩间隔或延长幕；重算读窗 |
| 接缝顿一下 | 两侧速度是否匹配（第六节） | 改位移或时长；或换硬切 |
| 接缝闪一下底色 | 上一幕是否卸载太早 | 晚卸载 1–2 帧 |
| 同一元素位置跳 | 是否两条动画在抢同一个属性 | 一个属性只归一条 `anim`；定位与动画分开写 |
| 循环处卡一下 | 首尾的速度是否相同（不只是位置） | 让首尾共用同一条曲线；必要时硬切 |
| 动作对了但"没感觉" | 有没有预备和随动 | 加预备 20%、随动延迟 2–4 帧 |
| 全片都在动，但记不住 | 三级力度分布（`get_guide("text-events")` §5） | 大部分幕停下来，只留 1–2 处冲击 |
