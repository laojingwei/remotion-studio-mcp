# 示例：换一套自己的问诊

这个目录演示**问诊插件**怎么写。**它默认不生效**——`steps.json.example` 不是 `.json`，
宿主只认 `brief/steps.json`。想试就改名：

```bash
cd plugins/_example-brief/brief
mv steps.json.example steps.json
```

改完直接跑 `intake` 或 `get_brief`，**不用重启**。想撤回就改回 `.example`。

## 能改什么

| 能改 | 不能改 |
|---|---|
| 步骤数量（不用凑 9 或 11 步） | 内置字段的含义（`goal` 就是目标，不能改成别的） |
| 步骤标题、顺序、合并拆分 | 设计锁怎么从字段推导（只有 form/density/motionLevel/transitionTone/effects/bgTone/mood 这 7 个字段参与） |
| 每步问哪些字段、问什么问题 | —— |
| 哪些步算"必答"（`core: false` 就不进必答） | —— |

## 三种模式

**替换**（`"mode": "replace"` 或不写）：整套换掉内置的 11 步。

**追加**（`"mode": "append"`）：接在内置 11 步后面，编号自动从 12 开始。
适合"内置的挺好，我就想多问两件事"。

**直接给数组**：最省事，等价于 replace。

```json
[
  { "title": "第一步", "required": [["goal", "目标"]], "questions": ["要达成什么？"] }
]
```

## 扩展字段（`x.` 前缀）

插件可以问内置 45 个字段之外的东西，写法是给 key 加 `x.` 前缀：

```json
{ "required": [["x.competitor", "主要竞品"]] }
```

答案会落在 `brief.x.competitor`，通过 `save_brief(x: {"competitor": "..."})` 写入。

**必须知道的限制**：`x` 字段**不参与设计锁推导**。也就是说，问了不会改变密度/转场/音效档位——
它只作记录，给 agent 后面写稿、写分镜时参考。想知道"填了到底影响什么"，看
`shared/designLock.ts` 的 `deriveDesignLock`：它只读那 7 个内置字段。

如果某个扩展字段确实该影响画面，正确做法是让用户把它映射到内置字段（比如让用户选一个 `density` 档位），
而不是指望 `x` 生效。

## 编号规则

**编号由宿主按数组顺序自动分配（1、2、3…），你写的 `no` 会被忽略。**
这样不会出现"两个都写 1"或"1、2、5 跳号"——步号是 `save_brief(step=N)` 与进度判定的键，
重复和跳号都会让进度算错，而且错得很隐蔽。

想调整顺序就调数组顺序。

## 换模板之后旧工程会怎样

`brief.json` 里已存的**内置字段**照常保留；`brief.x` 里的旧扩展字段也保留但不显示。
`brief.steps`（已完成到第几步）只在编号还存在的步骤上生效——换模板后进度可能"看起来倒退"，
这是预期行为：新流程本来就没问过那些新问题。

## 装了两个问诊插件怎么办

问诊是单例（一个工程只有一份 brief），所以只用一个：按插件 id 排序取第一个，
其余的会在 `list_plugins` 与 `intake` 的输出里被点名"忽略"。要换用请停用另一个。
