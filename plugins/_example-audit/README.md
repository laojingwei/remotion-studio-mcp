# 画质守门员（示例：钩子插件）

一个**不改数据、只提意见**的插件。它演示了钩子能介入的三个位置：

| 钩子 | 时机 | 这个插件干什么 |
|---|---|---|
| `audit:rules` | 调 `audit_project` 体检时 | 单幕 < 1.2s、字幕 > 42 字、连续三幕同类型 |
| `ops:review` | 每次写入工程之后 | 一批删了 > 3 幕、标题 > 24 字 |
| `brief:derive` | 推导设计锁时 | 把自定义问诊字段 `x.competitor` 翻成一条验收规则 |

## 怎么启用

```bash
mv plugins/_example-audit/plugin.ts.example plugins/_example-audit/plugin.ts
```

**不重启、不重新打包**，下次自检就带上它的意见。

## 为什么默认不启用

它会在每一次自检里加几句话。示例不该改变别人的默认体验——尤其"连续三幕同类型"
这种规则，对不同风格的项目未必成立。想用就自己打开，不想用随时删文件夹。

## 它说出来的话长什么样

```
契约体检通过 ✅（5 项确认）
提醒：
  ⚠️ [quality-gatekeeper] 1 幕短于 1.20s：开场（0.83s） —— 观众还没看清就切走了
  ⚠️ [quality-gatekeeper] 1 条字幕超过 42 字：第 3 幕（57 字） —— 拆成两条
```

`[quality-gatekeeper]` 这个前缀是宿主强制加的：**用户必须看得出这条不是宿主的判断**。
插件报的 `blocking` 会让体检整体不通过，所以归属必须清楚，不能让插件隐身。

## 三条边界（写插件前请先看）

1. **同步**。钩子跑在保存工程/自检的同步路径上，不能 await、不能发网络请求。
   超过 30ms 会被记一条"太慢"。
2. **只读**。入参是深冻结快照，改它直接抛错。想改数据请走 MCP 工具，不要指望钩子。
3. **代码就是代码**。`plugin.ts` 是被 `import()` 执行的任意代码，顶层就能读写文件。
   这里的"只读"是 API 的约定，**不是沙箱**——装一个代码插件等于在这台机器上装一个程序。

## 出错了会怎样

- 加载失败：`list_plugins` 里这个插件标「加载失败」并给出原因，服务照常。
- 运行抛错：记一笔，其余插件继续；连续失败 3 次自动摘除，避免刷日志。
- 返回结构写错：当它没说话（不报错、不影响你的保存请求）。
