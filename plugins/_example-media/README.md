# 示例插件：素材清洗

把 `plugin.ts.example` 改名成 `plugin.ts` 即生效（**改完立刻可用，不用重启**）。

## 它做什么

| 类型 | 动作 | 门槛 |
|---|---|---|
| 图片（jpg/jpeg/webp） | 最长边限 1920、重编码（顺带丢掉 EXIF，含拍摄地这类隐私信息） | 原件 ≥ 200KB，且处理后必须更小 |
| 音频（wav/mp3/m4a/aac） | 响度拉到 -16 LUFS | 有 ffmpeg |
| 视频 | **不动** | 转码是分钟级的，不该卡在上传的同步等待里 |
| PNG | **不动** | 重编码会丢透明通道，体积也没优势 |

## 它证明了什么

**规则因团队而异，所以该插件化。**「我们的图最大 1920 宽」「所有旁白都要 -16 LUFS」
是每家自己的口径，硬编码在宿主里只会得到十个不一致的实现。

而且它**零新依赖**：宿主已经有 ffmpeg（Remotion 自带那份），通过 `ctx.ffmpeg`
交给插件。不用为了处理图片给宿主装 sharp。

## 关键的三个写法

**1. 不处理就返回 `null`，不是抛错。**

```ts
if (!ctx.ffmpeg) return null;        // 这台机器没有处理能力，原样入库才是对的
if (ctx.kind !== "image") return null; // 不管的类型直接放行
```

返回 `null` 表示"我看过了，不动手"。抛错会被记成失败并进 `list_plugins`，
而"这个格式我不处理"是你的设计，不是故障。

**2. 产物写进 `ctx.tmpDir`，不要碰 `ctx.file`。**

```ts
const out = path.join(ctx.tmpDir, "out.jpg");
spawnSync(ctx.ffmpeg, ["-y", "-i", ctx.file, "-vf", "scale=...", out]);
return { file: out };   // 宿主读走，然后自己清理 tmpDir
```

`ctx.file` 是**原文件，只读**。写它会让宿主失去"原文件永远在"的保证——
那样用户就再也回不去了。

**3. 觉得不值得处理就不返回。**

示例里两条：重编码后更大 → 返回 `null`；文件小于 200KB → 干脆不进处理。
**"处理"不等于"无脑跑一遍命令"**，每个处理器都该有自己的门槛，
否则用户得到的是画质更差、体积更大的"优化"。

## 产物落在哪

处理结果写成**新文件**：`1712ab-cd.png` → `1712ab-cd@x1y2z.jpg`（`@` 后面是处理器指纹）。

原文件一直保留。所以：

- 处理错了 → 把工程引用改回原文件名就行
- 停用插件 → 新上传不再处理，**已处理的文件不受影响**
- 换插件版本 → 指纹变 → 新文件名，新旧可对比

溯源记在 `data/projects/<工程 id>/asset-provenance.json`。

## 它会自动改工程里已有的图吗

**不会。** 自动处理只对**新上传**生效——已经引用的旧文件不能凭空变，
否则用户会发现"我什么都没做，画面变了"。

要对已有素材跑：`reprocess_assets` 工具（默认只预览，`dryRun=false` 才写）。
它产出新文件但**不会自动改工程的引用**，换不换由你决定。

## 注意

`plugin.ts` 是 `import()` 执行的任意代码。这个示例只用 ffmpeg 处理素材，
但你完全可以在这里 `fs.rmSync`。**装代码插件 = 在这台机器上装一个程序**，
确认来源再用。
