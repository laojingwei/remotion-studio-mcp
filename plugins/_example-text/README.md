# 团队口径（示例：文本处理插件）

把公司术语、品牌写法、口头禅统一成一套说法。**只改字，不改结构。**

## 生效位置

| 时机 | 做什么 |
|---|---|
| `set_subtitle` 写字幕 | 拆分之前先过一遍（拆完再改会让每屏字数算错） |
| `save_script` 写稿件 | 每段 `text` 各过一遍；`sourceText`（用户原话）**不动** |
| `transform_project_text` | 手动把规则套到**已有**字幕上，默认只预览 |

需求契约（`brief`）不过这一层：那里的字是用户和你对齐用的，被词表改写会让对齐结果和原话对不上。

## 怎么启用

```bash
mv plugins/_example-text/plugin.ts.example plugins/_example-text/plugin.ts
```

**不用重启**。之后新写的字幕就会带上规则。

## 改什么

```
我们的产品 / 咱们的产品 / 本产品  →  星河 OS
用户们                          →  用户
进行一个…的操作                  →  操作
然后，/ 就是说，/ 其实吧，        →  删掉（只删句首）
０-９                          →  0-9（全角转半角）
```

## 三条必须守住的规矩

**1. 必须幂等。** 处理两次的结果要和处理一次一样。

反例：`text.replace("视频", "短视频")` —— 第二次会变成「短短视频」。
反例：句首口头禅只删一次 —— 「然后就是说……」第二次保存又会少一个，结果取决于存了几次。

写替换表时问自己一句：**替换后的词会不会再次命中规则？**

**2. 只改字，不改结构。** 不要加换行、拆句子、加序号。断句是宿主的活。

**3. 宁可少改，不要猜。** 这段代码在用户每次保存时都会跑，改错了会一遍遍改错。
全删空了要原样返回（示例里最后那行兜底就是干这个的）。

## 宿主给的护栏

| 情况 | 后果 |
|---|---|
| 返回空字符串 | **拒收**，保留原文本（防止一句话把字幕清空） |
| 输出长度 > 输入 ×3 + 200 | **拒收**（基本是插件把整句替换成了模板） |
| 抛错 | 跳过这个插件，其余继续；连续失败 3 次自动摘除 |
| 文本 > 20000 字 | 整条链跳过（它跑在保存路径上） |
| 处理 > 30ms | 记一条"太慢"警告 |

被改动时工具回执里会写「插件处理：「house-style」12→11 字」——**用户的字被谁改了必须看得见**。

## 一句话判断值不值得做

规则**因团队而异**的才做成插件（术语表、品牌写法、断句偏好）。
有客观标准的事（响度归一、视频转码）应该内置，别让十个插件给出十个不一致的答案。
